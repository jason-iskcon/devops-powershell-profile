# v3.0.0 — K-system aliases from one grammar, now for Bash and Zsh

> **DRAFT. Not published.** Paste this into a GitHub Release once the version is confirmed. Before
> publishing, set the release date, and refresh the verification links below to the final commit's
> CI run. Links are absolute because a Release page cannot resolve repository-relative ones; the
> CHANGELOG link resolves once the `v3.0.0` tag exists.

The kubectl "K system" (`kgp`, `kzgpw`, `kxpaa`, …) is now generated from a single grammar, which
makes it possible to offer the same 788 aliases in Bash and Zsh, with tab completion that
understands what each alias stands for. 785 of the 788 aliases behave exactly as in 2.0.0.
**This is a major release because it removes two helper functions and corrects three aliases;
read "Breaking changes" before upgrading.**

## Highlights

- **Bash and Zsh** (Linux): all 788 aliases as shell functions, installed with
  `sh posix/install.sh`. `kzgp <TAB>` completes as `kubectl --namespace=kube-system get pods <TAB>`,
  using kubectl's own completion.
- **One source of truth**: `k-grammar.toml` generates the PowerShell and the Bash/Zsh files, and CI
  fails if a generated file is out of date.
- **A compatibility contract you can check**: the 788 original aliases are listed in a frozen
  manifest (`tests/k-aliases.tsv`, hash-pinned) and every shell is tested against it. New aliases
  go through a separate, marked mechanism and cannot change an existing one.
- **Safer installers**: the Bash/Zsh installer is idempotent and reversible, never overwrites a
  backup, writes through symlinks, refuses damaged markers instead of losing your data, and
  uninstalling one shell keeps the files the other still uses.
- **A test suite that can fail**: in 2.0.0 `Test-Profile.ps1` reported "All tests passed" even
  with nothing tested. It now checks every kubectl function and runs in CI on Linux and Windows.

## Breaking changes

1. **`dy` and `f` are removed.** They never worked through the K aliases (the documented
   `k create deploy nginx --image=nginx dy` passes the literal word `dy`). They did work when passed
   straight to the native command, for example `kubectl delete pod x (f)`; that is gone. Write
   `--dry-run=client -o=yaml` and `--force --grace-period=0` instead.
2. **`kgn`, `kdn`, `kxn` now mean `get|describe|delete namespaces`**, as the README always said. In
   2.0.0 each was defined twice and the second definition (`… --namespace`) won. These are the only
   three aliases that behave differently from 2.0.0.
3. **The kubectl aliases moved to `k-aliases.ps1`**, loaded from the profile's own folder.
   `Install-Profile.ps1` copies both files. If you copy only the profile by hand you get a start-up
   warning and no kubectl aliases until you add `k-aliases.ps1` beside it.

## Upgrading from 2.0.0

```powershell
git pull                        # or download the release
.\Install-Profile.ps1 -Force    # backs up your current profile, installs both files
. $PROFILE                      # or open a new window
.\Test-Profile.ps1              # should pass
```

Then search your own scripts for `dy`, `f` and `kgn`/`kdn`/`kxn`.

## Install

```powershell
.\Install-Profile.ps1           # Windows PowerShell: modules + profile + k-aliases.ps1
```

```sh
sh posix/install.sh             # Bash or Zsh, chosen from $SHELL (or --shell bash|zsh|both)
sh posix/install.sh --dry-run   # see what would change
sh posix/install.sh uninstall   # remove the block and the copied files
```

## Safety notes

- **Several aliases delete things.** `kx…` is `kubectl delete`, and with `aa` it means `--all`:
  `kxpaa` is `kubectl delete pods --all` in the current namespace. `ta` is
  `terraform apply --auto-approve`. These are unchanged and documented in the README.
- The Bash/Zsh functions contain no `eval`; arguments are forwarded with `"$@"`, and the fixed
  arguments are shell-quoted. Tab completion loads kubectl's own completion script, so it runs
  whatever `kubectl` is first on your `PATH`.
- A `kubectl` shell function of your own (a wrapper adding a context or logging) is honoured by the
  Bash/Zsh aliases; a wrapper must call `command kubectl`, not one of these aliases. An
  `alias kubectl=…` is not expanded. Loading the file removes any alias that has the same name as one
  of the functions for that session (for example the oh-my-zsh kubectl plugin's `kgp`).
- Neither installer uses `sudo`. The Bash/Zsh installer only removes the files it installed and makes
  a timestamped backup of a shell file before changing it. `Install-Profile.ps1` backs up your
  current profile when run with `-Force`, and asks before overwriting it otherwise.

## Also fixed

- `Install-Profile.ps1`, `Test-Profile.ps1` and `Export-Anki.ps1` **did not parse on Windows PowerShell
  5.1** (UTF-8 without a BOM; a `✓` becomes a curly quote). They now start with a BOM. Earlier releases
  documented 5.1 support without it ever having been run.
- `Test-Profile.ps1` could never fail, its `-Quiz` mode was unreachable, and one failure was reported
  as "Failed: 5". All fixed.

## Known limitations

- Completion of live resource names (pod names, …) comes from kubectl and needs a cluster; it is
  **not covered by the tests**. The tests do check that kubectl is asked the right question and that
  flags and flag values complete.
- Bash completion needs bash 4.1+ and the bash-completion package; Zsh completion needs `compinit`.
- Only the kubectl K system is ported to Bash/Zsh; the Git and Terraform aliases and the PowerShell
  helpers are not.
- Uninstalling leaves an empty shell file behind if the installer created it, and a file that did
  not end in a newline gains one.
- The Python test suite runs on Linux; it is not run on Windows or macOS.
